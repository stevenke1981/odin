# Third-party notices

Odin's newly authored source is offered under the included MIT license. The design references public Serena functionality and standard protocol/SDK interfaces. This is not a formal clean-room claim or a legal compliance certification.

Odin 0.2.0 does not vendor Serena or SolidLSP source, does not depend on their packages, and removes the external Serena MCP bridge. Public references and the comparison matrix remain documentation only. No Serena or JetBrains plugin is included or required by Odin's native runtime.

Rust dependencies and external language servers/debug adapters retain their respective licenses. The real Cargo.lock is committed. `verification/sbom.cdx.json`, `verification/license-inventory.json`, and `docs/THIRD_PARTY_LICENSES.txt` inventory all resolved target variants, checksums and license texts. `cargo deny check licenses` and strict Cargo audit are executed separately. Some crates omit license files from their tarballs; exact upstream texts and their source hashes are recorded under `docs/dependency-licenses/`. Historical validation-only language/debug servers are not bundled merely because they were tested. The Windows LSP recipe now explicitly bundles basedpyright, typescript-language-server, TypeScript, bash-language-server, LuaLS, gopls and csharp-ls, their fixed npm dependencies, and portable Node.js, Go and .NET SDK runtimes. Exact versions, official archive/module provenance and every shipped asset hash are recorded in `backends/manifest.json`; upstream license/copyright files accompany the payload. Rust toolchains/debug adapters are not part of this LSP payload. This inventory is not a legal compliance certification; upstream license terms continue to apply.

The Cargo inventory covers crate packages. The static Linux build also links Rust standard-library and native runtime code; their upstream license and copyright texts are shipped in [runtime notices](docs/THIRD_PARTY_RUNTIME_NOTICES.txt), with exact source hashes recorded separately under `verification/runtime-notices-v3-*`. External build tools are not bundled merely because they were used to compile the app. This notice inventory does not certify legal compliance.

The Python test fixtures are newly authored protocol mocks, not actual language servers or debuggers. Python is test/verification tooling, not a dependency of the Odin Rust runtime; a separately selected backend may have its own runtime requirements.

## Expanded Windows language-server programs

The Windows payload also includes fixed Slint LSP, clangd, Taplo, YAML LS, Marksman, Ruff, ty, vtsls and rust-analyzer. Exact official asset/source URLs and hashes are in `packaging/lsp-native-sources.json` and the shipped `backends/manifest.json`. Executables retain their own licenses; installing them does not turn their code into MIT-licensed Odin source. Rust toolchains and ShellCheck are not bundled.

Slint LSP is a separate GPL-3.0-only program, accompanied by the license text and compressed corresponding-source sidecar with source/build inventory. The sidecar's input hashes are checked; rebuilding the upstream binary has not been executed. The presence of another Slint license text is not a claim that the standalone LSP is offered under the royalty-free API license.

The native notice collector records Cargo.lock supersets (including dev/non-Windows packages), actual embedded Marksman NuGet dependency metadata, upstream supplied texts, source URLs, and declared supplemental license-text gaps. Its status is `WITH_DECLARED_NOTICE_GAPS`, not a complete linked SBOM or legal certification. Component gap counts: Taplo 6, Ruff 9, ty 9, rust-analyzer 7, Marksman 3; supersets overlap. Review the shipped `licenses/` and `sources/` inventory and upstream terms for redistribution. No missing upstream text is replaced with invented attribution. See `docs/EXPANDED_LSP.md` and `docs/LSP_PAYLOAD_BUILDER.md`.

The standalone Slint folder also contains the three pinned Microsoft Visual C++ runtime DLLs needed by its actual PE import closure. They come from the official Visual Studio x64 redistribution directory, retain Microsoft licenses/notices and valid Microsoft signatures, and are inventoried in `slint/app-local-runtime.json`. These app-local files are separate from Odin's own runtime dependency inventory. System DLLs and UCRT remain provided by Windows; the builder does not install or register a global runtime.
